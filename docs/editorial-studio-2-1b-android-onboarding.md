# Editorial Studio 2.0 · 1-B Android 탐색·최초 안내

## 목표
Android 기존 4개 하단 메뉴(영상 추가, 작업, 결과, 설정) 및 Native Bridge를 보존하면서 작업 기록이 없는 사용자에게 작업 방식 선택과 연결 요구사항을 짧게 안내한다.

## 구현
- `android/web/index.html`: 영상 추가 설명 바로 뒤 `firstRunGuide` 배치. 파일/마이크/오프라인 3가지 작업 진입 안내와 닫기 동작, 하단 메뉴의 `aria-controls` 연결.
- `android/web/app.js`: 초기 Native `status` 결과에 작업이 없고 안내를 닫지 않았을 때만 표시. 사용자가 닫으면 같은 앱 WebView의 `localStorage`에 **안내 닫힘 여부만** 기록한다. 비밀키나 작업 데이터는 저장하지 않는다.
- 파일 안내: API 연결이 없으면 기존 연결 설정으로 이동하며, 준비되어 있으면 기존 파일 선택 버튼에 포커스. 파일 선택 권한이나 Native 처리 로직은 변경하지 않는다.
- 마이크 안내: 기존 온디바이스 마이크 항목으로 이동해 선택하게 한다. 사용자가 직접 누르기 전 녹음·API 호출 없음.
- 오프라인 안내: 기존 Vosk `details`를 펼치고 모델 관리 진입 버튼에 포커스. 자동 다운로드/음성 처리 없음.
- `android/web/styles.css`: 기존 Editorial Studio 2.0 공통 토큰을 사용하여 여백·기본 버튼 폭·360px 이하 세로 배치. 새 색상·그림자·라운드 없음.
- `android/tests/editorial-2-1b-onboarding.test.mjs`: 조건부 표시, 사용자 선택 경로, 저장 데이터/기존 ID/보안 회귀 검사.

## 동작 및 범위 제약
- 기존 첫 화면 선택(`jobs.length ? 'jobs' : 'video'`) 보존. 작업 기록이 존재하면 안내 패널 노출하지 않는다.
- 사용자가 안내를 닫아도 기존 기능, 작업 기록, API 키, SQLite 데이터에 영향 없음.
- 로그인, 클라우드 동기화, 새 인식 모델·탭, 자동 API 연결, 자동 오디오 전송을 만들지 않는다.
- 기존 작업/결과/설정 탐색 기능 및 `aria-current` 처리 유지.
- 브라우저 스토리지 사용 불가 환경에서도 오류 없이 기본 안내 표시 가능.

## QA
1. 새로운 사용자 작업 0건: 영상 추가 초기 진입, 안내 표시, 세 가지 작업 진입 컨트롤의 포커스/스크롤.
2. 작업 기록 1건 이상: 작업 화면 초기 진입, 안내 숨김.
3. 닫기 후 앱 재실행: 안내 숨김, 작업 정보 불변.
4. API 미연결: 파일 진입 시 연결 설정으로 이동, 온디바이스·Vosk 안내는 개인 API 키를 요구하지 않음.
5. 320/360/390/432px, 라이트·다크, 글꼴 100%·160%, Android 키보드, 화면 회전, 접근성 포커스.
6. 기존 Web/Android CI, 에뮬레이터, 1-A 컴포넌트 테스트 성공.
