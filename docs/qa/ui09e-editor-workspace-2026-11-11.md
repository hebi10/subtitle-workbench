# UI-09-E — 자막 편집 작업 공간

기준일: 2026-11-11
저장소: https://github.com/hebi10/subtitle-workbench
기준: UI-09-A 실제 Android 15 QA 데이터(영상 연결 27자막 / 영상 미연결 15자막 / 라이트·다크 / 폰트 100·160%).
선행 자료: https://docs.google.com/document/d/173tB-fnTHztgRHDsjAVV1MAgir74aSxrNUUznhm7HNg/edit

## 수정 범위

- Android WebView `editorView`에 한정하여 저장 상태 → 선택 자막 정보/재생 → 보조 편집 도구(접힘) → 자막 실제 편집 필드의 순서로 재배치한다.
- 기존 `editorFeedback`은 sticky로 유지하고, 선택 자막의 요약 영역을 단순화한다.
- `editorTools`를 접힌 보조 영역으로 유지하면서 영상 처음부터 미리보기, 내보내기, Undo/Redo, 검색·필터·위치 이동을 그 안에 그룹화한다. `previewSelectedCue`와 이전·다음 자막 이동은 현재 자막 영역에서 계속 제공한다.
- 선택 자막 상세 입력은 시작/종료 시간 → 원문 → 번역 → 화자 순서로 조정한다. 실제 자막 데이터 값이나 텍스트 변환·정렬 규칙은 변경하지 않는다.
- 입력 시간은 소수점 셋째 자리까지 화면 표시만 정규화한다(`17.150000000000002` → `17.15`). 입력값을 사용자가 수정하지 않으면 저장 데이터의 원래 값은 보존된다.

## 유지 조건

- 동일 `id`, 기존 Native Bridge(`preview`, `saveCues`, `loadJob`)와 편집 히스토리, 자동 저장·재시도·실패 시 이동 차단 정책을 유지한다.
- 선택 자막 재생 위치 전달, 자막 12개/페이지, 검색·검수 필터, 시간/번호 이동, 자막 분할·병합, 편집 제한 상태를 유지한다.
- WebView 내부 별도 플레이어나 서버/유료 API 기능은 추가하지 않는다. 신규 의존성 없음.
- 기존 라이트(화이트/중성 회색)·다크(차콜/블랙), 48px 버튼 기준, 단일 문서 스크롤, 그림자·반경 없는 디자인 유지.
- 이번 브랜치는 앱 키, Android 배포, Play AAB, 스토어 등록정보, 비밀값을 수정하지 않는다.

## 확인 시나리오

1. Android/WebView에서 저장 도구막대가 컨텍스트보다 앞서 있고, 추가 편집 도구는 기본 접힘.
2. 선택된 자막의 시간/원문/번역/화자가 위계대로 배치되며 입력 중 IME·포커스 보존.
3. 부동소수점 장문 시간은 3자리 소수로 표시, 수정 후 Native 저장 및 재진입 때 동일 값 보존.
4. 필터·검색·시간/번호 이동, 페이지 경계(12/13), Undo/Redo, 분할·병합, 저장 실패/재시도/영상 미리보기 차단 등 기존 회귀 테스트 통과.
5. 320/390/800px, 라이트/다크, 390×480 가상 키보드 뷰포트에서 가로 오버플로와 sticky 상태 검증.
6. 실제 API 음성 인식·물리 기기 키보드/TalkBack은 이번 PR의 자동 QA로 완료를 주장하지 않는다.
